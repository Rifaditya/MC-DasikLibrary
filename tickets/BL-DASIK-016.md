## 🎯 1. Problem Statement & Player Impact
Currently, client configuration screens generated by `UniversalConfigScreen` bind reflection getters and setters exclusively to in-memory config class fields. While `DynamicGameRuleConfigSync.syncToGameRule` pushes updates from Mod Menu to server GameRules on save, opening Mod Menu while inside an existing singleplayer world displays stale default values from `config/<modid>.json` rather than the active world's live `GameRules` in `level.dat`. Furthermore, if values are changed and saved in-game, global JSON templates can inadvertently be mutated, and players cannot distinguish whether they are editing world-specific rules or global new-world templates.

## 🔬 2. Architectural Blueprint & Target Implementation

### 1. `DynamicGameRuleConfigSync` API Expansion
Add clean public static query and wrapper methods in `net.dasik.social.api.client.gui.DynamicGameRuleConfigSync`:
* `public static boolean isSingleplayerActive()`: Returns `true` if `Minecraft.getInstance().getSingleplayerServer() != null`.
* `public static Object getGameRuleValue(String gameRuleName)`: Queries the active singleplayer server's `GameRules` directly and returns the typed value (`Boolean`, `Integer`, etc.), or `null` if not in singleplayer or rule is missing.
* `public static <T> Supplier<T> worldAwareGetter(String gameRuleName, Supplier<T> fallback)`: Returns a supplier that queries the live GameRule when in singleplayer, falling back to `fallback.get()` when on the title screen.
* `public static <T> Consumer<T> worldAwareSetter(String gameRuleName, Consumer<T> configSetter)`: Returns a consumer that sets the active world's GameRule **ONLY** when in singleplayer, and calls `configSetter.accept(val)` when on the title screen.

### 2. `UniversalConfigScreen` Dual-Context Generation
Update `net.dasik.social.api.client.gui.UniversalConfigScreen`:
* **Context-Aware Title**:
  - In Singleplayer: `[Mod Name] — Active World: <World Name>`
  - On Title Screen: `[Mod Name] — Global Defaults (New Worlds)`
* **Top Notice Banner**: Injects an informational notice at index 0 of the general category clearly explaining the current context.
* **Dual-Context Field Option Bindings**:
  - When `annotation.syncGameRule() == true`:
    - In Singleplayer: Getter reads from `DynamicGameRuleConfigSync.getGameRuleValue()`.
    - In Singleplayer: Setter writes to `DynamicGameRuleConfigSync.syncToGameRule()` (updating `level.dat` GameRules without mutating global JSON).
    - On Title Screen: Standard reflection getter and setter targeting config class/instance.
* **Multiplayer Remote Client Safety**:
  - If connected to a remote multiplayer server (`Minecraft.getInstance().getCurrentServer() != null` or `!isSingleplayerActive()`), locks settings into a clear read-only info mode with a notice banner.
